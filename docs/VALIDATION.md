# 验证记录

## 2026-10-11 挂单网格；撤下自动轮动

### 研究：为什么做网格

用 OKX 公开历史数据，2024-11 到 2026-08，共 22 个月、211 个加密币（剔除了股票代币）。每个月能否参与测试只看当时近 30 天的成交额，不用事后数据挑币。成本按 OKX 普通用户费率：吃单 0.10% 加 0.05% 滑点，挂单 0.08%。OKX 接口查不到已下架币的历史，结果仍偏乐观。

- **大环境**：山寨币等权持有 −80%，BTC +11%（期间最大回撤 −53%）。
- **雷达动量排名**：和下周涨跌的相关系数 0.02，前 5 名比全体平均多涨 0.0%。没有预测力，所以撤下依赖它的自动轮动。
- **按上月回测挑币**：上个月最好的 5 个币，当月平均 +7.4%，下个月 −0.8%，全体平均 −0.7%。
- **RSI、区间策略**（产品默认仓位）：22 个月 −14% 和 −18%。
- **BTC 带动效应、暴跌抄底、BTC 均线开关**：扣费后都亏，或没有改善。
- **2% 挂单网格**：全体山寨币 −20%，55% 的月份赚钱。只做大币时：

  | 币 | 收益 | 赚钱的月份 |
  |---|---|---|
  | BTC | −2.8% | 64% |
  | ETH | +3.0% | 68% |
  | SOL | +9.7% | 77% |
  | XRP | +21.9% | 73% |

  同期直接持有的最大回撤在 −53% 到 −76% 之间。格距 1% 时 4 个币全都亏损，对参数很敏感。这只算继续验证的理由，不是盈利证据。

### 实现

- **白名单**：OKX 客户端新增只挂单（post-only）限价单和按本程序订单编号撤单。挂单必须带正价格，不能带 tgtCcy；普通限价单、条件单等其他类型一律拒绝；所有订单必须带本程序的订单编号。请求格式对照了 ccxt 4.5.84 的 OKX 实现。
- **网格逻辑**（`lab/grid.py`）：
  - 每格先存档再提交；
  - 每分钟用 `orders-pending` 加按编号查询来对账，只在订单终结时记账；
  - 买入成交后在高一格挂卖单；
  - 空仓且价格上涨超过一格时，整体上移；
  - 每次检查最多新挂 6 单。
- **失败处理**：
  - 提交结果不明：暂停，只按同一编号查询，不重发；
  - OKX 明确拒单：清掉这一格的挂单并暂停；
  - 已接受的挂单超过 2 分钟查不到：冻结。
- **退出**：暂停、到期、程序重启和出错时撤下全部挂单；触及亏损线时先撤单，再市价卖出。
- **限制**：网格最长 7 天，每日订单上限至少是格数的 2 倍；单笔策略仍最长 24 小时。
- **历史检验**：可以检验网格，取约 100 天（2400 根）小时数据；规则与实盘网格一致，挂单按格价成交。在真实 OKX 最近 100 天数据上，BTC、ETH、SOL、XRP 前段 +3% 到 +9%，后段 −0.2% 到 +1.6%，最大回撤都在 7.5% 以内；同期直接持有 +20% 到 +41%。
- **撤下自动轮动**：删除轮动的引擎、提示词和界面；选币雷达保留，用来筛选可交易的币。

### 验证

- `uv run python -m pytest -q`：100 项通过。网格测试使用模拟的 OKX 订单簿，覆盖：
  - 提交前存档、反向挂单、低买高卖记账；
  - 暂停撤单、部分成交后撤单再卖出；
  - 结果不明不重发、查到后恢复跟踪、拒单；
  - 亏损线先撤后卖、到期撤单、上移基准；
  - 有持仓时禁止改参数、实盘仍需两道开关；
  - 白名单拒绝普通限价单等、撤单只能按编号；
  - 网格回测。
- `node --check static/app.js`：通过。本机 Chromium 在 1440px 与 390px 下检查了网格设置、每格挂单列表，以及对真实 OKX 行情的网格回测：没有横向溢出，也没有脚本错误。

### 未验证

- 没有向 OKX（模拟盘或实盘）发过一笔真实挂单。post-only 挂单、撤单、`orders-pending` 的真实返回，以及 post-only 被拒时的错误码，都需要在 OKX 模拟盘上确认。
- 回测没有模拟挂单排队和部分成交，实际成交次数会更少。
- 网格在单边下跌中会被套到亏损线。

## 2026-09-30 选币雷达、全币种可交易范围与自动轮动

- 新增 `lab/scanner.py`。它只读 OKX 公开接口：`/public/instruments`、`/market/tickers` 各调一次，再对通过硬条件的币逐个读取日线，每次请求间隔 0.25 秒。
  - 硬条件：USDT 现货、状态正常、非稳定币或杠杆代币、非股票代币（OKX 把代币化美股也列为现货）、24h 成交额、买卖价差、上线天数、日线未中断、年化波动。
  - 打分：28 天与 7 天涨幅、相对 BTC 强弱、成交额取百分位加权，再加上是否在 50 日均线上方。
  - 字段名对照了 ccxt 4.5.84 的 OKX 实现。市值字段先留空，留给以后接入 CoinMarketCap。
- 可交易范围 = BTC-USDT、ETH-USDT 加上最新一次雷达通过筛选的币。OKX 客户端的下单白名单由这份名单生成，格式不符的交易对会被拒绝。跌出名单的币不再买入，但可以卖出、对账和续期，续期是为了让亏损线继续保护这笔持仓。
- 轮动模式：一个试验同一时间只持有一个币。空仓时每根新小时 K 线从雷达前 N 名里选币：规则策略买第一个出现买入信号的；LLM 策略只能选其中一个或持有，其他回答都按持有处理。持仓降到零碎币以下后，零碎币单独记录，然后回到空仓。雷达超过 3 小时未更新时不开新仓。所有下单前的检查与原来相同。
- 接入真实 OKX 公开行情后发现：没配密钥的客户端默认带模拟盘标记，读到的是模拟盘行情。模拟盘只有 568 个交易对，而真实市场有 1148 个；同一个 NEAR-USDT，模拟盘显示 24h 成交 5.5 亿 USDT，真实市场只有 4550 万。选币雷达、行情图和历史检验现在统一读真实市场的公开数据；模拟盘交易仍按模拟盘行情成交。修复后在真实行情上完整扫描一次：OKX 共 1148 个交易对，84 个币通过筛选，用时约 50 秒。
- 自查时修正了三处：
  - 持仓的币跌出名单后，原来无法续期，亏损线就保护不到它；
  - 上线天数上限原为 100，但一页日线最多只有 99 根已收盘的，会把所有币都排除，上限改为 90；
  - 日线中断的币原来不会被排除。
- `uv run python -m pytest -q`：93 项通过，新增 29 项，全部使用模拟对象或 MockTransport。`node --check static/app.js`：通过。
- 本机 Chromium 用写入的演示雷达数据，在 1440px 与 390px 宽度下检查：排名表、排除统计、固定／轮动切换、「用于试验」回填、轮动模式下的回测提示、扫描失败时保留上次结果。页面没有横向溢出，也没有脚本错误。
- 未验证：
  - 开发环境无法访问 OKX，没有对真实的全市场数据跑过雷达，也不知道真实扫描耗时和有多少币能通过筛选；
  - 轮动模式没有在模拟盘运行过；
  - 雷达得分没有任何盈利证据。

## 2026-09-30 接入 TypeSafe Jev

- LLM 策略新增「模型来源」：OpenRouter，或直接调用 TypeSafe 的 Jev（`POST https://api.typesafe.ai/v1/systemone`，一道 `choice` 题，选项 buy / sell / hold）。Jev 返回所选项、置信度和各选项概率，不返回文字理由和费用；页面显示 token 用量，费用按 TypeSafe 账单另计。
- 接口格式取自 PyPI 上 TypeSafe AI 官方发布的 `typesafe-sdk` 0.7.2 源码（校验了 wheel 的 sha256，只阅读未安装）；其中的数据结构由 `api.typesafe.ai/openapi.json` 生成。TypeSafe 官方文档站在开发环境无法访问。
- Key 通过只读的 `GET /v1/models` 验证，与其他密钥一样加密保存；错误只报告 HTTP 状态，不回显返回内容。两个来源的密钥分开保存、分开检查。
- `uv run python -m pytest -q`：64 项通过（新增 15 项，全部使用模拟对象或 MockTransport）；`node --check static/app.js`：通过；本机 Chromium 在 1440px 与 390px 下检查了来源切换、密钥对话框和连接失败提示。
- 未验证：开发环境无法访问 api.typesafe.ai，没有向真实 Jev 发送过请求，也没有观察它的真实回答、耗时与费用。

## 2026-09-27 LLM 决策策略

- 新增 `lab/llm.py` 与 LLM 策略：每根新收盘小时 K 线最多询问一次 OpenRouter 模型，回答只能是买入／卖出／持有。模型在引擎锁外调用，回答写入账本后由新一轮检查执行，因此到期、暂停、未决订单、亏损线、每日次数、仓位上限在下单前都会重新检查。
- OpenRouter Key 经 `GET /api/v1/key` 验证后与交易所凭证一样加密存放在 `data/`，接口与日志不回显。
- `uv run python -m pytest -q`：49 项通过（新增 17 项，全部使用模拟对象或 MockTransport）；`node --check static/app.js`：通过。
- 本机 Chromium 检查 1440px 与 390px：选择 LLM 后才显示模型字段，页面无横向溢出，历史检验按钮给出不可回测提示，密钥对话框可打开，无脚本错误。

## 2026-09-27 修复

- 策略检查只取一页 100 根小时 K 线，而 OKX 最新一页包含正在形成的那根，已收盘只有 99 根，首次检查即暂停。改为取两页。新增测试用 MockTransport 按真实分页格式返回数据，经真实 `OkxClient` 走完启动、检查、下单；修复前该测试失败。
- 买入手续费按币扣，全部卖出后账本留下低于最小下单量的零碎币，试验无法归档；触及亏损线的试验因此既不能续期也不能结束。现在低于最小下单量的零碎币可以归档，数量与估值写入归档和事件。
- OKX 单笔拒单返回顶层 code 1、原因在 sCode；此前只报告 1。现在报告 sCode，并写入冻结提示。拒单后的处理不变：仍冻结、不重发。
- 移除 Tailscale 远程访问与 `--origin` 参数，服务只供本机浏览器使用。删除未使用的旧策略框架代码（`lab/base.py` 与 `rsi.py` 中的旧 evaluate）。
- `uv run python -m pytest -q`：32 项通过；`node --check static/app.js`：通过。仍未使用任何真实或模拟账户凭证。
